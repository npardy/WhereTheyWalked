Search orchestration — You need to query multiple sources intelligently. FamilySearch has a free API. Newspapers.com, FindAGrave, and some census databases have varying levels of API access. For others, you're either scraping or using web search as a proxy.
Entity resolution — Matching "William James Longmire b. 1803 Ulverston" to records that might say "Wm. J. Longmire" or "W. Longmire" or have OCR errors. This is where AI actually adds value — fuzzy matching, context-aware disambiguation.
Synthesis — Taking 3-7 fragmentary sources and writing a coherent 200-word biography. LLMs are good at this.
Confidence scoring — Distinguishing "definitely this person" from "probably" from "might be." Users need to know what's verified vs. inferred.
The real questions:

What's the moat? Ancestry already has hints and record matching. The gap is that their output is fragmented — you get a list of records, not a narrative. The product opportunity is the synthesis layer — turning raw records into readable history.

Scope control — A 500-person tree researched thoroughly would cost real money in API calls and take hours of compute. You'd need tiers: "direct line only," "4 generations," "full tree," "notable figures only."
Data source licensing — FamilySearch is open. Ancestry's data isn't. Newspapers.com has paywalled archives. You'd either need partnerships, or you rely on what's freely searchable and position accordingly.

def geocode_location(name, city, state, location_type):
    # Try exact first
    result = geocode(f"{name}, {city}, {state}")
    if result:
        return result, confidence="exact"
    
    # Fallback based on type
    if location_type == "cemetery":

    elif location_type == "church":
        # Try variations: remove "Church of", etc.
        result = geocode(f"{simplified_name}, {city}")
    
    if result:
        return result, confidence="approximate"
